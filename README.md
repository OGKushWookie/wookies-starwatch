# Wookie's Starwatch

Overlay 1.11.0 / portable launcher 2.2.0 private beta — unofficial, display-only companion for the Steam/Electron build of Stellar Odyssey.

## Base discovery dust heatmap

Open **Dust** for a separate, local heatmap of the Steam main galaxy. Galaxy, Region, and Local change the scale around the selected coordinate; **My location** centers your current Z-1 position. Click the map, use its arrow keys (Shift moves ten coordinates), or enter exact X/Y coordinates to inspect a point. **Plan route** hands the selected coordinate to the existing manual route planner; it never travels.

Color represents the distance term only: `10 × distance in coordinate units to the nearest starter`. The fixed 0–19,000 display scale stays the same at every zoom and is not a reward cap. The installed wiki documents `base dust = star value + 20 × body count + nearest-starter distance in LY`. The inspector shows that full base value when complete star/body metadata has been observed. Missing fields remain unknown, not zero. Player bonuses, tax and server rounding are not modeled.

Known systems are labeled as already known, not repeatable discovery rewards. Other coordinates are **unverified**: they may already be discovered or hidden. The heatmap does not prove a fresh discovery is available. Its distance layer works without an API key. Star/body details come from already-loaded game views and the existing personal journal/user feed; this release does **not** download a second full public catalogue or retain every public system from the perfect-node feed.

Raster work is lazy, chunked and cached, and runs only while the Dust tab is visible. It does not modify the game map, draw extra markers there, make additional API calls, or upload dust data. Up to 6,000 compact observed star/body records and the selected view are kept locally, evicting the oldest records at the bound. The canvas and coordinate drafts stay stable through background refreshes.

Overlay 1.11.0 is a signed automatic update for launcher 2.2.0; no launcher replacement is required.

## Nearest public perfect nodes

In **Nodes**, choose Rocky, Icy, Gas, Crystal, or All resources to see the nearest ten matching systems with exact 100% nodes. The list follows the live player position after a jump or teleport, without opening the game map. Select **Plan route** for the existing fuel/cooldown/portal-aware itinerary. A personal official API key is required once per PC; Steam linking is not required for the public index.

Launcher 2.2.0 streams the gzip-compressed `/api/public/systems` feed on a native background thread, discards non-perfect records, and atomically saves a Windows-encrypted compact index. It uses ETags, refreshes at most hourly, preserves cached results on failure, and honors the daily reset after a quota response. The full response never enters the game renderer or personal cloud sync. Gold map glows are limited to already loaded coordinates. Public results are main-galaxy (Z 1) records; hidden systems are absent.

Publicly mapped systems remain distinct from personal systems seen. Journal bodies now feed the personal perfect-node observations, with journal `date` correctly interpreted as milliseconds. The default complete journal is still used; this release does not walk paginated journal history.

Upgrading from 2.1.0 requires replacing the EXE once, because the native API helper changed. Existing local API keys, Steam links, settings, and favorites are preserved.

This is a private-beta build for a small trusted test group. Read `PRIVACY.md` and `KNOWN ISSUES.md` before enabling shared sync. The launcher is not yet commercially code-signed; verify the supplied SHA-256 checksums rather than disabling Windows security software.

## Start

1. Double-click `WookiesStarwatch.exe` before or after starting **Stellar Odyssey**.
2. Leave the launcher running in the Windows notification area. It detects the game and injects the overlay automatically.
3. Use the slim **Starwatch** tab on the right edge of the game, press **Alt+I**, or double-click the notification-area icon.

The launcher waits when the game is closed and automatically reconnects after the game or renderer restarts. **Start with Windows** is an optional notification-area setting; it is never enabled without the user's click.

## What it does

- Passively indexes systems that the native galaxy map has already loaded and highlights systems containing 100% resource nodes with a native golden map-layer glow cloned from the game’s blue squad-station effect. It lives in the same transformed map group. Each animation frame now performs only a lightweight attachment/scale check; a full node resync happens only after a native map rebuild or during the normal periodic refresh, avoiding the map-opening slowdown while retaining the anti-blink repair.
- Uses a full-height collapsible right-edge cockpit drawer with a readable vertical navigation rail, contextual header, independently scrolling content, and fixed status footer. On normal desktop-width windows, opening it reserves the drawer’s width and reflows the game into the remaining space instead of covering it; closing it restores the full game width. On narrow windows the drawer overlays the game to avoid making the game unusably thin. Click outside the drawer, press **Esc** or **Alt+I**, or use its close button to dismiss it; the engine-ready badge remains independent.
- Reads the currently loaded squad roster.
- Builds your own live profile directly from loaded player stores, including levels, lifetime statistics (without inventory-material clutter), pets, equipped gear, and installed gear catalysts with their applied bonus values.
- Optionally refreshes your own profile, equipped gear/catalysts, pets, XP/RSS totals, complete travel journal, and squadron-station list from the official read-only Steam Public API. The journal supplies accurate total jumps and visited coordinates without inventing resource-node quality that the API does not provide.
- Passively caches public profile display data after you open a profile using the game's own player search: levels, stats, pets, ship gear, and catalysts embedded in gear.
- Creates selectable basic profiles for loaded squad members and the currently viewed public-profile route. Missing public fields, including gear, remain blank until the game itself exposes them.
- Keeps the Profiles and XP Rates selectors focused on squad members and explicitly favorited players. A normally viewed non-squad profile can be added with the clearly labeled **Favorite** button.
- Records XP snapshots for your live profile and public profiles the game loads, then estimates Battling, Gathering, Crafting, and Exploring XP per hour over rolling 6-hour, 24-hour, 7-day, or all-observed windows. Rankings prefer a reliable active-session estimate per player and otherwise use a robust wall-clock fallback clearly labeled on that row.
- Keeps the native top bar at its normal height while the drawer is open by grouping the four game boosts behind a compact display-only button. The popover reads live boost state already present in the client and exposes the current bonus, tier and countdown on hover without activating or purchasing anything.
- Keeps the original per-player XP detail view in the **XP** tab and shows separate, tie-aware Battling and Gathering XP/hour leaderboards in a dedicated **Ranks** tab. The boards cover squad members and favorites currently included by the XP filter, highlight your live placement, and keep players with less than 10 minutes of comparable observations in a separate calibrating count.
- Adds a tie-aware **RSS per Hour** board to the Ranks tab for you, squad members, and favorites. It calculates robust wall-clock RSS gain rates from repeated cumulative profile snapshots over the selected 6-hour, 24-hour, 7-day, or all-observed window. Totals are captured only when normal gameplay naturally loads them; leaderboard values are kept only for the official rank display and never enter RSS-rate history.
- Provides optional shared-database sync. When explicitly enabled, sanitized public profile, XP, RSS, account map-index, and opted-in completed-battle observations are sent to a separately hosted companion service and merged with eligible observations. Compact ranking summaries synchronize in the background; detailed history loads only for the XP-tab player. The overlay never polls profiles or map locations; it only contributes data the game already loaded because of normal player actions.
- Lets favorites follow the same detected Stellar Odyssey account across PCs through one-click Steam authentication. Each installation receives its own revocable device credential automatically, so nothing needs to be copied between PCs. The previous private-code flow remains under advanced settings as a recovery fallback.
- Adds a **Market** tab for the official API's hourly buy/sell history over the last 24 hours. This is price history, not individual live listings.
- Adds official dungeon, solo-dungeon, and rune event cards plus colored map markers, optional new-event notifications, passive loaded-client fallback, and visible feed/key-health status.
- Adds a perfect-node finder with resource/planet filtering and automatic cross-device persistence for timestamped exact-100 observations. Its exact shortest-route planner accepts perfect nodes, events, squad stations, and starter systems; live squad portals are used only when they reduce flown distance, every flown leg is split into legal jumps using the active account's verified 100/120 fuel capacity, and all routes remain display-only.
- Adds an **Ops** tab for laboratory, stellarium, offline-action, boost, and pet deadlines when the API exposes an unambiguous timestamp, plus a current-session XP/RSS/travel/perfect-node recap.
- Expands Market with sell-price sparklines, 24-hour low/high, volatility, threshold alerts, and an optional manual holdings estimate that does not read or display inventory.
- Expands Roster into a squad-operations board with fresh-profile readiness, squadron stations, bonuses, and buildings when available.
- Adds a profile Build Lab for hypothetical PvP and catalyst modifiers, side-by-side estimates, saved presets, and importable `SOI1` share codes. Its guarded model learns from deduplicated completed battles while showing profile-matched versus lower-weight log evidence; unknown opponent catalysts remain explicitly unknown and server RNG is never presented as certain.
- Adds a dedicated **PvM** tab that uses the installed game's own local `simulateBattle`, maximum-level search, and stat optimizer. Select any standard NPC family and level, edit gear/stat/skill/clone/station/catalyst inputs, then compare the current snapshot with the test build using identical random sequences. Maximum-level and four-stat optimizer tools use an adjustable win-rate target, simulation accuracy, search cap, and stat budget.
- Labels ranking evidence by age, sample count, and observed span. A rate containing a strong statistical spike is withheld rather than ranked until a clean window is available.
- Securely checks the separately hosted companion service for signed `overlay.js` updates before injection. Routine UI and tracking releases install automatically without touching the game installation or downloading a new ZIP.
- Highlights squad/friend locations only when the game has already exposed recent coordinates to the client. Location markers expire after 30 minutes.
- Observes the engine cooldown countdown already rendered on the galaxy map and provides configurable one-shot ready alerts: an audio chime, in-game toast, gold screen-edge flash, persistent ready badge, optional Windows desktop notification, and background taskbar attention. ## Compliance boundary

The overlay does **not** send gameplay actions, game WebSocket messages, navigate profiles, click controls, travel, gather, or automate any game action. Without an API key it only reads in-memory client state plus responses caused by your normal actions. After the user explicitly adds a key, the native helper makes only documented `GET` requests to `https://steamapi.stellarodyssey.app/api/public/` for `user`, `journal`, `stations`, `market`, `dungeons`, `solodungeons`, and `activerunes`. The game publisher describes these endpoints as read-only and intended for trackers, dashboards, map viewers, and Discord bots.

The helper enforces its own persistent cache, so `/user`, `/journal`, `/stations`, `/dungeons`, `/solodungeons`, and `/activerunes` are fetched no more often than once every 30 minutes and `/market` no more often than once per hour, including across launcher restarts. This stays within the documented limit of 50 requests per endpoint per key per UTC day. The helper cannot proxy arbitrary paths and never receives commands that change game state.

Shared sync is disabled by default. If you enable it, the overlay makes HTTPS requests only to the separate companion service at `https://stellar-odyssey-intel-sync.sthess28.workers.dev` (or a replacement endpoint you enter). It does not use the game server for synchronization. Because the game rules supplied with this project prohibit extensions from sending game-server requests, confirm with the game's operators that an independent, informational community database is acceptable before distributing shared sync publicly.

The launcher checks that companion host when it starts and no more than once every 30 minutes while running. It accepts only manifests signed by the public key embedded in the launcher and only overlay files matching the signed SHA-256 checksum. Update traffic never goes to the game server. A future release that changes the native launcher or official-API allow-list may still require a manual EXE refresh; ordinary overlay UI releases install and re-inject automatically.

Cooldown notifications are informational only. They observe the visible client countdown and never activate the engine or initiate travel. Desktop notifications are disabled by default and can be enabled through the Alerts tab. Launcher 2.1.0 delivers them through its Windows notification-area process without browser permission; Windows Focus Assist or system notification settings can still suppress a banner.

Personal map observations are passive. The updated official journal also supplies visited coordinates and body/node quality. Launcher 2.2.0 independently builds a global perfect-node index from the official public systems feed; it does not mark those public systems personally visited. Golden 100% halos are drawn only at coordinates already loaded on the native map. Other players are never requested through the official account endpoint.

XP and RSS-rate tracking are passive. Your own loaded totals are sampled locally; another player requires normally loaded public-profile observations. With Sync enabled, those observations can come from different participating overlay users. XP wall-clock rates need at least 10 minutes and include idle/offline gaps. Active-session XP needs at least three positive adjacent intervals, no more than ten minutes apart, totaling at least ten minutes; it excludes unchanged, skipped-level, and extreme outlier intervals. Sparse profiles therefore calibrate rather than pretending their active playtime is known. RSS remains a wall-clock calculation from cumulative profile totals and requires at least 60 minutes.

Battle learning is passive and separately switchable in the Sync tab. It reads only completed Arena and Squadron results already present in the game's client stores and never starts, repeats, queues, or influences a battle. Before upload, player and squadron names are replaced with attacker/defender slot tokens and all internal IDs are discarded. The database deduplicates observations. Profile/API values are labeled observed, behavior inferred from logs is given lower weight, and hidden catalyst values remain unknown. Estimates are informational and cannot reproduce server randomness exactly.

The PvM lab is separate from shared battle learning. It imports pure calculation functions from the game bundle already installed and running on the PC, reads only the current player's locally loaded build, and performs simulations entirely in memory. PvM inputs and results are not uploaded to the shared database. It does not call a game API, open an NPC, start combat, spend resources, or automate a game action. Although the underlying rules are official client code, individual battle outcomes still vary because combat uses randomness; increasing simulation runs reduces sampling noise.

## Use the NPC Combat Lab

1. Open the overlay and select **PvM**. The current battle target and complete live build load automatically when available.
2. Choose an NPC family and level. Change any values in **Test build** while the untouched current snapshot remains the baseline.
3. Select **Run current vs test** for win rate, average battle length, and surviving clone health. Current and Test use the same deterministic random sequence for a cleaner comparison.
4. Select **Scan maximum level** to compare the highest level that meets the chosen win-rate target.
5. Set the total stat budget and select **Optimize stat allocation** to search power, precision, evasion, and hull. Applying the result changes only the informational Test build.

Use **Reload current build** after changing gear, catalysts, clones, station bonuses, or assigned stats in the game. Use **Reset test changes** to discard hypothetical edits. None of these controls change the game build itself.

Sanitized overlay state is saved in the game's browser storage under `so-intel-overlay-v1`. Steam passwords, game cookies, game tokens, API keys, raw user responses, inventory materials, and chat content are never stored there or uploaded. The official API key and minimized API caches are encrypted under `%LOCALAPPDATA%\Stellar Odyssey Intel Overlay` with Windows DPAPI for the current Windows user. Select **Remove key from this PC** to delete both. When Steam linking is used, a random credential for this installation is stored locally; the service stores only its SHA-256 hash and it can be revoked by selecting **Disconnect this device**.

## Connect the official read-only API

1. Run the portable version 2.1.0 launcher once on each PC.
2. In Stellar Odyssey, open your profile's API-key area and generate or copy your personal key.
3. Start the overlay, open **Sync**, paste the key under **Official read-only API**, and select **Save key & connect**.
4. Repeat only the one-time key entry on each PC where you use the overlay. Normal launches reuse the Windows-encrypted key automatically.

This does not replace **Connect with Steam**. The API key reads your own official game data; Steam identifies the account to the separate shared-history service so favorites and pooled observations follow you between PCs.

## Enable shared history and cross-PC favorites

The release includes the Cloudflare Worker + D1 source in **Sync Service**. The shared instance is deployed and its address is prefilled in the overlay; enabling it remains an explicit choice.

1. Open your own in-game profile so the overlay can detect the loaded Stellar Odyssey account.
2. Open the overlay's **Sync** tab and select **Connect with Steam**.
3. Confirm the Steam account in the browser window and return to the game. Shared history is enabled after approval.
4. On another PC, repeat those steps with the same Steam account. Favorites and observed history load automatically; no code is copied.

Favorites sync by genuine local-change time, and a fresh device cannot replace an existing list until the user actually edits it. Systems seen and 100% node systems form an account-specific union across linked PCs. Shared XP and RSS samples are de-duplicated into one observation per player per minute. The client keeps its 30-day view locally; the service retains seven days of raw detail, compacts older records to hourly rollups, and preserves exact lifetime endpoints for all-observed rates.

Use the **Rules** tab to clear the overlay cache. Before uninstalling, use **Sync → Remove key from this PC** if an official key was saved; then delete this folder. The overlay does not modify the installed game files.
